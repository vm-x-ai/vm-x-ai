# OpenAPI / UI SDK Codegen

> **Scope:** this page covers the **REST client** generated from the API's
> OpenAPI spec and consumed by the UI. Database/Kysely codegen
> (`nx run api:codegen` → `packages/api/src/storage/entities.generated.ts`)
> is a different generator and is documented in
> [`database.md`](./database.md). Both exist; they are not interchangeable.

The UI consumes the API through a fully-typed client generated by
[`@hey-api/openapi-ts`](https://heyapi.dev). The generated client lives in
`packages/ui/src/clients/api/`.

## TL;DR workflow

```bash
# 1. Make API changes (controllers, DTOs) — add/adjust Swagger decorators
# 2. Start the API locally (it serves the OpenAPI document)
pnpm exec nx run api:serve
# 3. Wait for it to be ready
curl -s http://localhost:3030/api/docs-json | head -c 80   # should be JSON
# 4. Regenerate the SDK from the live spec
pnpm exec nx run ui:gen-client
```

`ui:gen-client` runs `pnpx @hey-api/openapi-ts -f openapi-ts.api.config.ts`
inside `packages/ui`. It is **not** a build-cached Nx target — it always hits
the URL in the config, so the API must be running and reachable at that URL
before you invoke it.

The generated files (`sdk.gen.ts`, `types.gen.ts`, `zod.gen.ts`,
`client.gen.ts`, and `@tanstack/react-query` hooks) are **committed** to the
repo so the UI project doesn't depend on a running API at build time. Always
commit the regenerated files alongside the API changes that produced them.

## When to regenerate

Re-run `ui:gen-client` whenever any of the following change in the API:

- A controller's route, HTTP verb, path parameters, query parameters, or
  `operationId`
- A DTO's shape, field names, types, or `@ApiProperty` metadata
  (`nullable`, `required`, `description`, `example`, enum members)
- The set of response status codes / `@ApiOkResponse` / `@ApiResponse`
  declarations on an endpoint
- Tags, security requirements, or any other Swagger metadata that ends up
  in the spec

## How the spec is produced and served

The OpenAPI document is **built at API boot time** from NestJS Swagger
decorators (`@ApiOperation`, `@ApiOkResponse`, `@ApiProperty`, etc.) on the
controllers and DTOs in `packages/api/src/`. There is no checked-in
`openapi.json` — the spec exists only in memory and is materialized on
request.

Wiring lives in `packages/api/src/openapi.ts` (`setupOpenAPIDocumentation`),
called from `packages/api/src/main.ts` after `setGlobalPrefix(basePath)`.
Two endpoints are exposed (paths use the configured `BASE_PATH`, which is
`/api` locally):

| URL                                   | Purpose                                        |
| ------------------------------------- | ---------------------------------------------- |
| `http://localhost:3030/api/docs-json` | Raw OpenAPI JSON — consumed by `ui:gen-client` |
| `http://localhost:3030/api/docs`      | [Scalar](https://scalar.com) API reference UI  |

`setupOpenAPIDocumentation` also injects hand-written OIDC provider paths
(`/oauth2/authorize`, `/oauth2/token`, `/oauth2/userinfo`,
`/oauth2/revoke`, `/oauth2/.well-known/openid-configuration`) into the
document, since those are served by the OIDC provider rather than by a
NestJS controller. They appear in the generated SDK as
`getApiOauth2*` / `postApiOauth2*` functions.

`packages/ui/openapi-ts.api.config.ts` points the codegen at the JSON URL:

```typescript
export default defineConfig({
  input: 'http://localhost:3030/api/docs-json',
  output: 'src/clients/api',
  // ...
});
```

If you change the API's `PORT` or `BASE_PATH` (e.g. for a non-default dev
setup), update this config to match.

## Plugins enabled

| Plugin                  | What it produces                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `@hey-api/typescript`   | TypeScript types from each schema (`types.gen.ts`, `enums: 'typescript'`)                                               |
| `@hey-api/client-next`  | A typed fetch-based SDK + client (`sdk.gen.ts`, `client.gen.ts`)                                                        |
| `@tanstack/react-query` | React-Query hooks per endpoint                                                                                          |
| `zod`                   | Runtime Zod schemas mirroring the OpenAPI schemas (`zod.gen.ts`) — `metadata: true` and inferred request/response types |

## Consuming the generated client

The barrel at `packages/ui/src/clients/api/index.ts` re-exports every
endpoint function and type. Import by `operationId`-derived name:

```typescript
import { getWorkspaces, createAiResource, type AiResourceEntity } from '@/clients/api';

const { data, error } = await getWorkspaces();
```

Auth is wired through a shared interceptor in
`packages/ui/src/clients/client-api-utils.ts` (`authInterceptor`), which
pulls the next-auth session and stamps `Authorization: Bearer <token>` onto
every outgoing request. Server-side helpers live alongside it in
`server-api-utils.ts`. The configured client itself lives in
`packages/ui/src/clients/api/client.gen.ts`.

For data fetching inside React components, prefer the React Query hooks
emitted by the `@tanstack/react-query` plugin (under
`packages/ui/src/clients/api/@tanstack/`) over calling `sdk.gen.ts`
functions directly — they give you caching, suspense, and invalidation for
free.

## Common pitfalls

**The codegen failed with "is not a valid JSON Schema"** — the URL it's
hitting probably returns HTML (Next.js dev server, an auth redirect, or a
404). Verify with `curl <url>` first.

**Generated types don't include my new endpoint** — the API server was
running an older build when codegen fired. Restart `api:serve` after
finishing your DTO/controller changes, then re-run codegen.

**Generated client returns `unknown` for a response field** — the controller
method is missing `@ApiOkResponse` or the DTO doesn't have `@ApiProperty`
on that field. Fix the decorator and re-run.

## Authoring API endpoints with codegen in mind

- Always annotate controllers with `@ApiOperation({ operationId })` — the
  `operationId` becomes the SDK function name (`getCompletionAuditMetadataKeys`,
  `createApiKey`, etc.).
- Always annotate response shapes with `@ApiOkResponse({ type: ... })` —
  otherwise the SDK return type degrades to `unknown`.
- For DTOs, every field needs an `@ApiProperty({...})` decorator. The
  description, `nullable`, `required`, and `example` fields all flow into
  the OpenAPI doc and into Scalar.
- Avoid `additionalProperties: true` on `@ApiProperty` — Scalar can render it
  but the codegen produces `Record<string, unknown>` which loses precision.
